📚 Теория

Как работает Spring MVC

HTTP-запрос → DispatcherServlet → Controller → Service → JSON-ответ

DispatcherServlet — центральный сервлет Spring. Находит нужный контроллер по URL и HTTP-методу, вызывает метод, сериализует результат в JSON.

DTO и Jackson

DTO (Data Transfer Object) — Java-класс, описывающий структуру JSON.

Jackson — библиотека сериализации, встроена в Spring Boot:

  • Java-объект → JSON (при @RestController)
  • JSON → Java-объект (при @RequestBody)

record (Java 14+) — идеален для DTO:

  • Неизменяемый
  • Автогенерация конструктора, геттеров, equals, hashCode, toString
  • Короче обычного класса

Формат Instant в JSON

Jackson сериализует Instant в ISO-8601 с UTC:

"2026-10-09T12:26:02.119400100Z"

Z в конце означает UTC (zone offset Z = +00:00).

Шаг 2. Создать DTO

package com.loskutnikov.booking.dto;

import java.time.Instant;

public record HelloResponse(String message, Instant timestamp) {
}

Шаг 3. Создать контроллер

package com.loskutnikov.booking.controller;

import com.loskutnikov.booking.dto.HelloResponse;
import org.springframework.web.bind.annotation.*;
import java.time.Instant;

@RestController
@RequestMapping("/api/v1")
public class HelloController {

    @GetMapping("/hello")
    public HelloResponse hello(@RequestParam(defaultValue = "world") String name) {
        return new HelloResponse("Hello, " + name + "!", Instant.now());
    }
}

Шаг 4. Запустить и проверить

GET http://localhost:8080/api/v1/hello
→ {"message":"Hello, world!","timestamp":"2026-10-09T12:26:02Z"}

GET http://localhost:8080/api/v1/hello?name=Igor
→ {"message":"Hello, Igor!","timestamp":"..."}

Шаг 5. PathVariable и несколько эндпоинтов

@RestController
@RequestMapping("/api/v1/events")
public class EventController {

    @GetMapping("/count")
    public CountResponse eventsCount(@RequestParam(defaultValue = "1") Integer count) {
        return new CountResponse(count, Instant.now());
    }

    @GetMapping("/{id}")
    public EventResponse eventById(@PathVariable Long id) {
        return new EventResponse(id, "Event #" + id, Status.AVAILABLE);
    }
}

🐞 Частые ошибки на практике

1. Забыл @RestController — написал @Controller
При @Controller возвращаемый объект воспринимается как имя view (HTML-шаблона). Spring пытается найти файл HelloResponse.html, не находит → ошибка 500 или пустой ответ. Решение: для REST всегда @RestController.
2. Дублирование пути в @RequestMapping и @GetMapping
@RequestMapping("/api/v1/events")
public class EventController {
    @GetMapping("/api/v1/events")   // ❌ получится /api/v1/events/api/v1/events
    public List<EventResponse> all() { ... }
}
Решение: метод дописывает путь относительно класса. Пиши @GetMapping (пустой) или @GetMapping("/{id}").
3. Смешивание @PathVariable и @RequestParam
@GetMapping("/{id}")
public EventResponse get(@RequestParam Long id) { ... }   // ❌ не сработает
Значение 5 в /events/5 — это часть пути, а не query. Решение: @PathVariable Long id.
4. Имя @PathVariable не совпадает с URL
@GetMapping("/{eventId}")
public EventResponse get(@PathVariable Long id) { ... }   // ❌ при null — 500
Spring ищет плейсхолдер по имени переменной. Решение: либо одинаковые имена (eventId/eventId), либо явно: @PathVariable("eventId") Long id.
5. Возврат null из контроллера
@GetMapping("/hello")
public HelloResponse hello() {
    return null;   // ❌ → 200 OK с пустым телом
}
Spring вернёт 200 OK с пустым телом. Клиент получит Content-Length: 0 и не сможет распарсить JSON. Решение: возвращай ResponseEntity или всегда непустой объект.
6. Не задан defaultValue для опционального @RequestParam
@GetMapping("/hello")
public HelloResponse hello(@RequestParam String name) { ... }   // ❌ 400 без ?name=
Без ?name= Spring вернёт 400 «Required request parameter 'name' is not present». Решение: @RequestParam(defaultValue = "world") или @RequestParam(required = false).
7. Возврат Entity напрямую (привычка из туториалов)
Хотя Entity может выглядеть как DTO, в реальном проекте это опасно: утекут служебные поля, Lazy-поля JPA уронят сериализацию, клиент привяжется к структуре БД. Решение: всегда возвращай DTO и маппируй явно.
8. Ожидание, что Jackson сериализует LocalDateTime «как строку»
Без модуля jackson-datatype-jsr310 (он уже включён в Spring Boot) LocalDateTime сериализуется в массив [2026,10,9,12,26,2]. В Spring Boot — по умолчанию строка ISO-8601, но если добавляешь свой ObjectMapper — легко сломать.
9. Опечатка в HTTP-методе: @GetMapper вместо @GetMapping
Компилятор не поймает — просто класс не будет обработан как контроллер. Решение: IDE обычно подсвечивает. Научись читать стектрейсы: «no mapping for GET /api/v1/hello».
10. Ответ 404 при запущенном приложении
Причины: 1) не тот server.port, 2) опечатка в пути, 3) метод не public, 4) контроллер в пакете вне основного (Spring сканирует от @SpringBootApplication вниз по пакетам). Решение: проверь @SpringBootApplication и структуру пакетов.

❓ Вопросы на собеседование

1. Чем отличается @Controller от @RestController?

@RestController = @Controller + @ResponseBody. Оба помечают класс как Spring MVC контроллер. Но @Controller возвращает имя view (HTML-шаблон для рендеринга), а @RestController — тело ответа (объект → JSON). Для REST API всегда @RestController.

2. В чём разница между @RequestParam и @PathVariable?

@PathVariable извлекает значение из URL-пути (/events/5 → id=5), применяется для идентификаторов ресурса. @RequestParam — из query-строки (/events?status=ACTIVE), применяется для фильтров, опций, пагинации. Оба могут быть опциональными через required=false или defaultValue.

3. Что такое DTO и почему не возвращать сразу Entity?

DTO (Data Transfer Object) — класс для передачи данных между слоями. Нельзя возвращать Entity напрямую, потому что: 1) утекут служебные поля (пароль, роли), 2) Lazy-поля JPA могут уронить сериализацию, 3) клиент привяжется к структуре БД, 4) нельзя навесить валидацию на вход. DTO — контракт API, Entity — внутренняя модель.

4. Что произойдёт, если клиент передаст ?count=abc вместо числа?

Spring попытается преобразовать "abc" в Integer, не сможет, бросит MethodArgumentTypeMismatchException, вернёт HTTP 400 Bad Request. Без кастомного @ExceptionHandler покажет стандартный ответ Spring (в браузере — HTML Whitelabel Error Page, в API-клиенте — JSON).

5. Зачем record для DTO?

record (Java 14+, финально — Java 16) — неизменяемый класс с автогенерацией конструктора, геттеров, equals, hashCode, toString. Для DTO это идеально: 1) коротко (1 строка вместо 30), 2) невозможно случайно изменить, 3) корректно работает в коллекциях, 4) явно выражает намерение «это просто данные».

6. Как Spring определяет, какой метод контроллера вызвать?

DispatcherServlet смотрит на @RequestMapping класса и HTTP-метод/путь метода. Ищет самое специфичное совпадение. Специфичность: точный путь (/count) > путь с плейсхолдером (/{id}). Если несколько методов подходят — Spring кинет IllegalStateException при старте (ambiguous mapping).

7. Что такое Jackson и как он связан со Spring Boot?

Jackson — библиотека для JSON-сериализации/десериализации. Spring Boot включает её автоматически через spring-boot-starter-web. При @RestController Spring использует Jackson, чтобы: 1) превратить возвращаемый Java-объект в JSON, 2) при @RequestBody — JSON в Java-объект. Можно настраивать через application.yml или свой ObjectMapper.

8. Как вернуть разные HTTP-статусы из контроллера?

Три способа: 1) вернуть ResponseEntity<T> — самый гибкий (ResponseEntity.status(201).body(obj)), 2) аннотация @ResponseStatus(HttpStatus.CREATED) на методе — для фиксированного статуса, 3) бросить исключение и обработать в @ExceptionHandler — для ошибочных сценариев. Для REST предпочтительнее ResponseEntity — явно видно, что вернётся.
