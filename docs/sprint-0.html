Java LTS vs не-LTS

LTS (Long-Term Support) — версии с долгосрочной поддержкой:

  • LTS: Java 8, 11, 17, 21, 25 — поддерживаются годами
  • Не-LTS: 9, 10, 12–16, 18–20, 22, 23, 24, 26 — поддержка ~6 месяцев
Правило: для продакшена и обучения — только LTS. Работодатели ищут знание LTS-версий, библиотеки тестируются именно под них.

Maven Wrapper

  • Maven — система сборки, ставится глобально
  • Maven Wrapper (mvnw, mvnw.cmd) — локальная копия Maven внутри проекта
  • Spring Initializr создаёт проект с wrapper'ом — глобальный Maven не нужен
  • Команды: ./mvnw clean install (Linux/Mac), mvnw.cmd clean install (Windows)

❓ Вопросы на собеседование

1. В чём разница между JDK, JRE и JVM?

JDK (Java Development Kit) = JRE + инструменты разработчика (javac, jar, jdb и др.). JRE (Java Runtime Environment) = JVM + библиотеки классов. JVM (Java Virtual Machine) — виртуальная машина, исполняющая байт-код. Для разработки нужен JDK, для запуска — достаточно JRE.

2. Что такое LTS-версия Java?

LTS (Long-Term Support) — версия с долгосрочной поддержкой (несколько лет). Не-LTS поддерживается ~6 месяцев. В продакшене используют LTS: Java 8, 11, 17, 21, 25. LTS-версии стабильнее, лучше документированы, библиотеки тестируются именно под них.

3. Зачем нужен Maven Wrapper?

Maven Wrapper (mvnw) — это локальная копия Maven внутри проекта. Позволяет: 1) не устанавливать Maven глобально, 2) зафиксировать версию Maven (у всех разработчиков одинаковая), 3) работать в CI/CD без установки Maven. Все современные Spring Boot проекты используют wrapper.

4. Что такое .gitignore и зачем он?

Файл, описывающий, какие файлы и папки не должны попадать в Git. Для Java-проектов это обычно: target/ (артефакты сборки), .idea/ и *.iml (настройки IDE), .DS_Store (Mac), *.log. Без него в репозиторий попадут локальные настройки, и у других разработчиков проект может сломаться.

5. Чем отличается mvn clean install от mvn clean package?

package — собирает JAR/WAR в target/, но не устанавливает его в локальный репозиторий ~/.m2. install — делает то же + копирует артефакт в локальный репозиторий, чтобы другие проекты могли его использовать как зависимость. Для обычной сборки приложения достаточно package.
