📚 Теория

Что такое OpenAPI

OpenAPI (ранее Swagger) — стандарт описания REST API в формате YAML/JSON. Спецификация описывает:

  • Эндпоинты (GET /api/v1/events)
  • Параметры (path, query, headers, body)
  • Ответы (статусы, схемы JSON)
  • Схемы DTO
  • Аутентификацию

Стандарт де-факто — его читают Postman, Insomnia, code generators, API gateways.

Swagger UI vs OpenAPI

ПонятиеЧто это
OpenAPIСпецификация — файл .json / .yaml с описанием API
Swagger UIВеб-интерфейс, который читает спецификацию и рисует интерактивную страницу
Это не одно и то же. OpenAPI — стандарт, Swagger UI — визуализация.

SpringDoc OpenAPI

SpringDoc сканирует контроллеры Spring ↓ Автоматически генерит OpenAPI-спецификацию ↓ Поднимает Swagger UI на /swagger-ui.html ↓ Отдаёт спецификацию на /v3/api-docs

Зависимость:

<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.6.0</version>
</dependency>

Альтернативы:

  • Springfox — старая библиотека, давно не поддерживается, не используем
  • springdoc-openapi — современный стандарт, работает со Spring Boot 3.x

Что даётся бесплатно (без аннотаций)

SpringDoc находит:

  • Все @RestController
  • Пути из @GetMapping, @PostMapping
  • Параметры @PathVariable, @RequestParam, @RequestBody
  • Схемы DTO из record / классов
  • Коды ответов из @ResponseStatus и ResponseEntity

Аннотации нужны для: описаний, примеров, дополнительных кодов ответов, скрытия служебных эндпоинтов.

Ключевые аннотации

АннотацияГдеЧто описывает
@TagКлассГруппа эндпоинтов в UI
@OperationМетодSummary + description эндпоинта
@ApiResponseМетодОдин HTTP-ответ (код + описание)
@ApiResponsesМетодОбёртка для нескольких @ApiResponse
@ParameterПараметрОписание параметра
@SchemaDTO / полеОписание DTO или поля
@ParameterObjectПараметрРазвернуть объект (например, Pageable) в набор query-параметров
@HiddenКласс/методСкрыть из документации
@SecurityRequirementКласс/методТребует аутентификации (пригодится в Спринте 6)

⚠️ Важно про импорты: @ApiResponse есть в двух пакетах:

  • io.swagger.v3.oas.annotations.responses.ApiResponse ✅ (правильный, OpenAPI 3)
  • io.swagger.annotations.ApiResponse ❌ (старый, Swagger 2, Springfox)

Метаданные API

@Bean OpenAPI — общая информация об API: название, версия, описание, контакты, лицензия, серверы.

<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.6.0</version>

Версию указываем явно — SpringDoc не управляется Spring Boot parent.

Шаг 2. Настройка application.yml

springdoc:

    path: /v3/api-docs
  swagger-ui:
    path: /swagger-ui.html
    operations-sorter: method
    tags-sorter: alpha
  show-actuator: false

Шаг 3. Класс метаданных OpenApiConfig

package com.loskutnikov.booking.config;

import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Contact;
import io.swagger.v3.oas.models.info.Info;
import io.swagger.v3.oas.models.info.License;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI ticketBookingOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("Ticket Booking Service API")
                        .description("REST API for booking tickets to events")
                        .version("v1")
                        .contact(new Contact()
                                .name("Igor Loskutnikov")
                                .email("igor@losku.ru")
                                .url("https://github.com/igorlosk"))
                        .license(new License()
                                .name("MIT License")
                                .url("https://opensource.org/licenses/MIT")));
    }
}

Шаг 4. Аннотации на контроллере

@RestController
@RequestMapping("/api/v1/events")
@Tag(name = "Events", description = "Operations for managing events")
public class EventController {

    @PostMapping
    @Operation(
            summary = "Create a new event",
            description = "Creates a new event with status AVAILABLE"
    )
    @ApiResponses({
            @ApiResponse(responseCode = "201", description = "Event created successfully"),
            @ApiResponse(responseCode = "400", description = "Invalid request body")
    })
    public ResponseEntity<EventResponse> create(@Valid @RequestBody CreateEventRequest request) { ... }

    @GetMapping
    @Operation(summary = "Get all events")
    @ApiResponse(responseCode = "200", description = "List of events")
    public Page<EventResponse> findAll(@ParameterObject Pageable pageable) { ... }

    @GetMapping("/{id}")
    @Operation(summary = "Get event by id")
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Event found"),
            @ApiResponse(responseCode = "404", description = "Event not found")
    })
    public EventResponse findById(
            @Parameter(description = "Event id", example = "1")
            @PathVariable Long id) { ... }
}

🐞 Частые ошибки на практике

1. Забыли @ParameterObject на Pageable
public Page<EventResponse> findAll(Pageable pageable)   // ❌ /v3/api-docs → 500
Без @ParameterObject SpringDoc пытается развернуть Pageable как один объект и падает. Решение: @ParameterObject Pageable pageable.
2. Импорт @ApiResponse из Swagger 2
import io.swagger.annotations.ApiResponse;   // ❌ старый, не работает
import io.swagger.v3.oas.annotations.responses.ApiResponse;  // ✅
IDEA часто подсказывает неправильный. Компилируется, но игнорируется SpringDoc. Решение: явно используй v3.oas.
3. Версия SpringDoc не указана
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <!-- нет version — Maven не найдёт artifact -->
</dependency>
SpringDoc — отдельный проект, не управляется Spring Boot parent. Решение: указывай <version>2.6.0</version>.
4. Несовместимая версия SpringDoc со Spring Boot
Spring Boot 3.5.x требует SpringDoc 2.6.0+. Если у тебя 2.3.0 — увидишь 500 на /v3/api-docs. Решение: сверься с [таблицей совместимости](https://springdoc.org).
5. Документирование через @ApiResponse только успешного ответа
@ApiResponse(responseCode = "200", description = "OK")   // только 200
Клиент не знает, что может быть 404. Решение: описывай все реалистичные коды (200 + 404, 201 + 400, и т.д.).
6. Забыли @Tag — эндпоинты в UI разбросаны
SpringDoc по умолчанию сгенерирует имя группы из имени класса (event-controller). Работает, но некрасиво. Решение: @Tag(name = "Events").
7. Не указаны примеры в @Schema / @Parameter
Примеры важны для клиента: он видит, какие данные ожидать. Особенно для новых API. Решение: используй example = "...".
8. Swagger UI заблокирован Spring Security
После Спринта 6 (Security) эндпоинты защищены — и Swagger UI тоже. Если не разрешить, UI вернёт 401. Решение: в SecurityConfig разрешить /swagger-ui/**, /v3/api-docs/**.
9. Смешивание Swagger 2 и OpenAPI 3 аннотаций
@Api, @ApiOperation, @ApiParam — из Swagger 2 (Springfox). @Tag, @Operation, @Parameter — из OpenAPI 3 (SpringDoc). Не смешивай. Для Spring Boot 3.x — только OpenAPI 3.
10. Открытие через /swagger-ui.html, а не /swagger-ui/index.html
Работает через редирект, но в новых версиях основной путь — /swagger-ui/index.html. Если html возвращает 404 — попробуй индекс.

❓ Вопросы на собеседование

1. Что такое OpenAPI и Swagger UI?

OpenAPI — стандарт описания REST API в формате YAML/JSON. Описывает эндпоинты, параметры, ответы, схемы DTO, аутентификацию. Swagger UI — веб-интерфейс, который читает OpenAPI-спецификацию и рисует интерактивную документацию. Можно кликать эндпоинты и делать запросы прямо из UI. Это не одно и то же: OpenAPI — стандарт, Swagger UI — визуализация. Дополнительно есть Swagger Editor, Swagger Codegen.

2. Чем SpringDoc отличается от Springfox?

Springfox — старая библиотека (Swagger 2), не поддерживается с 2020 года, не совместима со Spring Boot 3.x. Использовала аннотации @Api, @ApiOperation, @ApiParam. SpringDoc — современная, работает с OpenAPI 3 и Spring Boot 3.x. Аннотации: @Tag, @Operation, @Parameter, @Schema. Для новых проектов — только SpringDoc.

3. Что генерируется автоматически, а что требует аннотаций?

Автоматически: пути эндпоинтов, HTTP-методы, @PathVariable/@RequestParam/@RequestBody, схемы DTO (поля и типы), коды ответов из @ResponseStatus и ResponseEntity. Требуют аннотаций: описания (summary/description), примеры значений, дополнительные коды ответов (404, 409), группировка (@Tag), скрытие (@Hidden), метаданные API (название, контакты, лицензия). То есть структура — бесплатно, смысл — вручную.

4. Что такое @ParameterObject и зачем он нужен?

@ParameterObject — аннотация SpringDoc, которая говорит: «этот параметр — не одно значение, а объект, разверни его в набор полей». Пример: Pageable содержит page, size, sort. Без аннотации SpringDoc пытается развернуть Pageable как единый объект и часто падает с 500. С @ParameterObject в Swagger UI появляются три отдельных query-параметра.

5. Как документировать DTO через OpenAPI?

Аннотацией @Schema на классе DTO (общее описание) и на каждом поле (описание + пример). Пример: @Schema(description = "Event name", example = "Rock Concert"). В Swagger UI под схемой появятся описания полей и примеры значений. Для enum SpringDoc сам подставит Allowed values из Java-типа.

6. Почему @ApiResponse нужно импортировать из io.swagger.v3.oas.annotations.responses?

Потому что есть два пакета с этим именем: 1) io.swagger.v3.oas.annotations.responses.ApiResponse — OpenAPI 3 (для SpringDoc, актуальный), 2) io.swagger.annotations.ApiResponse — Swagger 2 (для Springfox, устаревший). IDEA часто подсказывает неправильный. Код компилируется, но SpringDoc игнорирует старую аннотацию — описания не появляются в UI. Всегда проверяй импорт: v3.oas.

7. Как связаны OpenAPI и code generation?

OpenAPI-спецификация — машинно-читаемый формат. Из неё можно генерировать клиентов для TypeScript, Python, Java, Go через OpenAPI Generator или Swagger Codegen. Плюс: клиент всегда синхронизирован с API, меньше ошибок. Также из спецификации генерируют моки для тестов, API gateways конфигурируют маршрутизацию. Это одна из причин, почему OpenAPI — стандарт индустрии.

8. Что делать, если Swagger UI нужен, но API защищён Spring Security?

В SecurityFilterChain добавить разрешение для путей Swagger: /swagger-ui/**, /swagger-ui.html, /v3/api-docs/**, /v3/api-docs.yaml. Иначе UI покажет 401/403 при загрузке спецификации. Дополнительно можно требовать аутентификацию для самих API-эндпоинтов, но UI и спецификацию оставить публичными. Разберём в Спринте 6.
